# Idle close + notice for the Local LLM service

## Context
Chrome stops the extension's MV3 service worker after 30s idle. The bridge content script's
`chrome.runtime` port to it then goes dead without `onDisconnect`, and every later page request
vanishes; Learn with LLM waits 45s and shows "The model did not start". The 20s stale-port fix in
`src/bridge/bridge.ts` was loaded (extension + tab reloaded) and asks still hang after a short idle.

The user wants the extension to own this: close the service itself on a fixed idle period
(25s, under Chrome's 30s), tell the page it closed, and restart cleanly on the next request.
The notice shows in the page; no new permissions.

## Step 0 — find why the stale-port fix did not help (before building)
Likely: the bridge's `inFlight` set holds ids whose reply never comes (e.g. a prompt the page
aborted: `router.ts` `abort()` deletes the router's `inFlight`, so the host's error is dropped),
so `inFlight.size > 0` keeps the dead port forever. Also possible: a reconnect from an old
content script after a worker restart is itself not answered.
- Temporarily add `console.debug("[bridge]", …)` in `bridge.ts` for connect/reuse/disconnect,
  `inFlight.size`, and each reply; rebuild, reload, reproduce (ask, idle 45s, ask), read the tab
  console with `read_console_messages` (pattern `\[bridge\]`). Remove the logs afterwards.
- The design below handles both causes; this step confirms which and checks the fallback is needed.

## Design (Project14_ChromeLLMBackend)

1. **Router idle close** — `src/background/router.ts`
   - Per `PageConn`: `lastActivity` and a timer. Reset on every message in (`port.onMessage` in
     `openConn`) and every `reply()` out (chunks included).
   - `const IDLE_CLOSE_MS = 25_000`. When it fires and the conn has no entries in `inFlight`:
     send `{ kind: "closed", reason: "idle" }`, then `port.disconnect()`. With requests in flight,
     re-arm instead (the host's `keepalive` already keeps the worker up while busy).
   - Disconnect runs the existing `onDisconnect` path (`releaseOwner`), so that page's idle
     sessions are destroyed. Fine for Learn with LLM (one session per ask); state it in the notice.
   - Playground conns (`llm-playground`) are excluded.

2. **Protocol** — `src/shared/protocol.ts`
   - Add `{ kind: "closed"; reason: "idle" }` (no `id`) to the page responses and to
     `parsePageResponse`; keep the parser strict. Add a test in `test/protocol.test.ts`.

3. **Bridge** — `src/bridge/bridge.ts`
   - Replace the `STALE_PORT_MS` logic with: on `closed` or `onDisconnect`, set `runtimePort = null`,
     fail every id in `inFlight` with `OperationError` (clears stale ids), and post
     `{ kind: "closed" }` to the page. Next request calls `connect()` → new port → wakes the worker.
   - Fallback if Step 0 shows a reconnect can go unanswered: after connecting, require the
     router's first message (add a `{ kind: "connected" }` sent from `onConnect`) within 3s;
     otherwise fail pending requests with "The extension stopped answering; reload the page".

4. **Polyfill** — `src/polyfill/polyfill.ts`
   - In `onPortMessage`, on `closed`: reject nothing extra (bridge already failed them) and
     `window.dispatchEvent(new CustomEvent("localllm:closed", { detail: { reason } }))`.
   - Document the event next to `localllm:ready` in `README.md`.

5. **Tests**
   - Unit: idle-close decision as a small pure helper (e.g. in `src/background/limits.ts` style:
     `shouldCloseIdle(lastActivity, now, inFlightCount)`), tested in `test/`.
   - e2e (`e2e/extension.spec.ts`): with a test hook shortening `IDLE_CLOSE_MS` (`__TEST__`
     define, like the existing `__test` globals), assert the page receives `localllm:closed`, then a
     new `LanguageModel.create()` succeeds.

## Learn with LLM (Project15_LearnWithLLM)
- `src/main.ts`: listen for `localllm:closed`; set `app.status.detail` to
  "Model service closed after 25s idle — your next ask restarts it" and re-render (same path as
  the `onDownload` status update). Restore "Ready" when the next ask starts.
- `src/llm/turn.ts`: no logic change; reword `START_TIMEOUT` to
  "The model service did not answer. Reload the page to reconnect." (it should now be rare).
- Update `src/llm/turn.test.ts` if it asserts the old text.
